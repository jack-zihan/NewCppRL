WHY .detach() ALONE DOESN'T FIX THE LEAK
═════════════════════════════════════════════════════════════════

return loss_out.detach(), step_taken  // In update_fn

What .detach() does:
┌────────────────────────────────────────────────────────────────┐
│ Original tensor:                                                │
│   data_ptr: 0x7f1234567000                                     │
│   requires_grad: True                                          │
│   grad_fn: <AddBackward>                                       │
│                                                                 │
│ After .detach():                                               │
│   data_ptr: 0x7f1234567000  ← SAME STORAGE!                   │
│   requires_grad: False      ← Gradient disabled               │
│   grad_fn: None             ← Computation graph cut           │
│                                                                 │
│ ❌ Memory still shared between original and detached          │
│ ❌ If original tensor kept alive, storage stays allocated     │
└────────────────────────────────────────────────────────────────┘

What we need: EXPLICIT DELETION
┌────────────────────────────────────────────────────────────────┐
│ del sampled_td  ← Removes reference from current scope        │
│ del loss_td     ← Removes reference from current scope        │
│                                                                 │
│ ✅ Python's reference counting decrements                      │
│ ✅ When ref_count reaches 0, memory deallocated               │
│ ✅ CUDA memory freed and returned to allocator                │
└────────────────────────────────────────────────────────────────┘
